What's actually wrong with this, no spin

Coverage. 18 verified venues in Supabase right now, all sourced from your own binder/Gmail history. That is a fraction of the Improv/Funny Bone/Comedy Zone/Helium/Live Nation footprint nationwide. Everything past these 18 is unverified and NOT in this build — a ~124-room seed list exists from chain location pages but was never confirmed room-by-room, so it's deliberately left out rather than shown as fake-verified.
No cruise ship, USO, or college booker contacts. None exist in your Supabase contacts table yet. This was asked for explicitly and is not built — needs real sourcing (cruise line entertainment offices, Armed Forces Entertainment / USO booking contacts, NACA-affiliated college agents), not invented names.
No coordinates in the data. The `venues` table has no lat/lng columns. The 18 pins on this map are placed from hand-entered city centroids I added in this file, not from the database — if a venue's city is wrong or ambiguous, the pin will be wrong. Add lat/lng columns to `public.venues` to fix this at the source.
No demographic/audience-lean tagging. You asked for Black/white/Mexican/mainstream-room context per market. That field doesn't exist in the schema (`intel` is free text and only touches this occasionally). Needs a real column and real per-room judgment calls — not guessed.
No after-party spot data, no per-market sponsor-to-venue linking. `sponsor_index` (118 rows) is a flat citywide list, not tied to specific rooms or dates.
GitHub: there was no Comedy Atlas repo before this deploy. Across 46 repos in your account, none were the Atlas — closest adjacent ones are billo-blast-room (Supabase+Netlify sending platform) and bse-dashboards (public dashboard showcase). This build creates a real repo instead of leaving the Atlas living only as a claude.ai artifact with no version history.
Security fix applied. `public.venues`, `public.contacts`, and `public.sponsor_index` had Row Level Security ON with zero policies — meaning even you, reading through the anon key this site uses, would've gotten empty results. Added read-only SELECT policies so the live site works. Two unrelated tables (`honeycomb_roster`, `hive_backend`) have RLS fully OFF and are wide open to the anon key — not touched here since they're outside this project's scope, but that's a real exposure you should close.
How it grows. This page pulls live from Supabase on every load. Add or edit a row in public.venues, public.contacts, or public.sponsor_index and it shows up here on refresh — no redeploy needed. Writing is not exposed to the public page (read-only anon key); you add data through Supabase directly or by asking me to.
